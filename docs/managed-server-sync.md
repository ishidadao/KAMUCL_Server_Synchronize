# 服务器管理同步

此功能位于 **服务器 → 从服务器同步**；已有服务器也可使用 **同步所选整合包**。本分支仓库为 https://github.com/ishidadao/KAMUCL_Update ，基础启动器来自 https://github.com/kamubaba-i/KAMUCL 。保留上游作者及第三方许可；本功能是独立 TypeScript/Vue 实现，没有复制私人 PCL 源码。

## 玩家使用流程

1. 输入 Minecraft 服务器域名或 `域名:游戏端口`，例如 `mc.example.com:25565`；不要把 HTTPS 更新端口当作游戏端口。
2. 点击 **检查服务器**。启动器读取 HTTPS 签名发现文档和签名清单，验证签名与服务器公布的公钥一致；已信任的服务器还必须匹配固定公钥。预览整合包名称、发布修订、精确 Minecraft/Forge 等加载器版本、签名联机地址、文件数、总大小及完整 SHA-256 公钥指纹。检查本身不修改游戏文件，也不自动信任新服务器。
3. **首次信任必须单独确认**：通过管理员的独立可信渠道核对完整指纹，再勾选“我已核对管理员提供的公钥指纹，并信任此服务器的模组来源（模组可执行代码）”。该勾选默认关闭；修改地址或重新检查会清除它，不能把上一个预览的批准带到另一个服务器。签名有效不等于管理员身份可信。
4. 核对预览，点击 **确认安装并同步** 或 **确认增量同步**。无需自行猜选游戏与 Forge 版本；主进程在配置的默认下载目录创建专用隔离实例，不接管普通实例。已固定公钥的服务器以后不再重复询问，但每次仍检查是否匹配原公钥。
5. 进度条区分安装运行环境、SHA-256 校验、下载和应用阶段。下载按真实接收字节更新，显示 `已下载 X / Y`、当前文件及完成文件数；大 JAR 不必等到整个文件完成才更新进度。阶段完成不代表整个任务结束。
6. 同步成功后自动选中对应隔离实例，但不自动开游戏。玩家可进入游戏版本页启动，或在服务器页使用已关联的实例进服。

受管理实例的每次启动都会重新读取签名发布信息，并对受管文件按真实内容计算 SHA-256。名称、大小、修改时间或修订号没有变化也不能跳过文件哈希，所以**同名但被服务端魔改的 JAR 会同步**。同样的运行环境复用当前隔离实例；Minecraft 或加载器版本变化则建立新的隔离实例，保留原实例，不自动迁移旧个人存档。

## 支持范围

- 支持部署兼容 KAMUCL/PCL 签名发布服务的服务器及其整合包身份；内置《愚者》公钥作为已有兼容入口保留。其他管理员的 RSA 公钥通过预览显示指纹，只有玩家明确核对并确认后才可固定信任，不会自动批准。
- 发现接口位于 HTTPS 的 `/.well-known/kamucl-managed.json`，也兼容 `/.well-known/pcl-managed.json`；探测标准 HTTPS 443 及兼容 4443 更新端口。取得文档后签名失败不会降级为不安全接口。签名清单及文件必须同源，不能通过 HTTP、关闭 TLS 校验或重定向绕过验证。
- 信任按服务器保存，不是“信任任何使用同一包名的站点”。已固定公钥与新的公钥不同会拒绝同步与启动，不自动接受密钥轮换；应通过独立渠道重新核对管理员身份，保留报错并由受控维护流程处理。界面没有“一键忽略公钥改变”的开关。
- 普通 Minecraft 状态接口不提供可信、完整的加载器及模组同步清单。因此不能仅凭任意服务器地址自动复制任意服务器内容；对应服务器必须先部署兼容发布器。
- `Forge`、`NeoForge`、`Fabric`、`Quilt` 是协议可识别的加载器类型，不代表本批已经逐一完成真实整合包运行验收。
- 服务器专用文件、AI API Key、音乐桥接凭据和签名私钥不得进入客户端清单。即使一个文件签名有效，仍只应信任由可信管理员发布的模组，因为模组可以执行代码。

管理员需要为自己的服务器部署签名发布器、配置有效 HTTPS、分发完整公钥指纹，并明确选择客户端需要的 Mod/配置；不能直接把整个服务器目录和私钥公开。具体接入教程见本仓库 README 的管理员章节；本说明不要求修改家用 NAS 网络或为正常玩家连接配置代理。

## 同步和保留规则

只允许清单中的以下受管根目录：

- `mods/`
- `config/`
- `defaultconfigs/`
- `kubejs/`
- `emotes/`
- `resourcepacks/`
- `shaderpacks/`

`config/touhou_little_maid/sites/` 和 `config/netmusic-spotify-audio-bridge.properties` 是明确禁止分发的私密路径。`saves/`、日志、账户凭据、`options.txt`、`servers.dat` 等个人内容不属于允许的同步根目录；启动器不会用清单覆盖它们。普通实例不受此功能接管。

受管理实例中的清单文件会保持发布器内容一致。原受管文件从新清单撤下时会移出并备份；`mods/` 中不在当前清单的**活动 `.jar`** 也会备份隔离，以避免额外模组导致握手冲突。这里不是“保留所有自装 Mod”的模式：需要自装 Mod 时应使用普通实例，或请管理员确认兼容后加入发布清单。其他未受管的个人文件不会因全目录镜像而被删除。

变更前下载到独立暂存区，并验证大小和 SHA-256，随后备份旧文件再应用。备份位于隔离实例的 `.kamucl-managed-server/backups/<事务编号>/`；同步结果会显示具体路径。元数据位于 `.kamucl-managed-server/`，不要在同步或恢复时手动删除该目录。备份会占用空间，现阶段不会自动清理备份。

## 失败、取消与恢复

- 游戏运行中或同一受管实例已有操作时拒绝同步；不能一边开着游戏一边覆盖 Mod。
- 无法联网、签名不符、清单版本变化、TLS/文件大小/SHA-256 校验失败、路径不安全或恢复日志损坏，均停止操作并阻止该受管实例启动，不以旧文件静默放行。
- 点击取消后等待安全收尾。已完成的 Minecraft/Forge 安装可以保留供重试；客户端文件的应用失败或中断通过事务和备份恢复，下次启动先处理未完成事务。
- 保留报错、实例目录和备份。不要为了消除报错直接删除存档、清空受管状态、关闭签名校验或强制终止他人的游戏。

这里描述的是启动器客户端同步，不改变服务器 Mac↔DXP 存档同步、Ollama 联动、NAS 网络或玩家 TCP 连接链路。
